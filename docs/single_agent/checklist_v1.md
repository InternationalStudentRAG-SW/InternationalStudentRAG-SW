# 질문 분석·근거 검증 체크리스트 v2 (검토용)

- 개정일: 2026-09-28
- 목적: ① 질문 분석, ② 검색 계획, ④ 충분성 검증이 같은 체크리스트를 사용하여 근거 부족과 사용자 조건 부족을 구분한다.
- 초안 작성자가 제시한 자료 범위: few-shot 예시 66개(한국어 38개 기준 분류), RAGAS 평가 질문 30개, 보유 문서 6개.
- 검토 상태: 구조·판정 규칙을 보완한 설계안이다. 이번 개정에서는 위 질문 전체와 PDF 원문을 다시 대조하지 않았다. 구체적인 규정·수치와 문서별 포함/미포함 주장은 검증 완료 사실로 취급하지 않는다.
- 역할: LLM은 질문별 항목 선택·분해·근거 판정의 초안을 만들고, 서버가 스키마·근거 ID·예산을 검증한다. 규정의 적용 범위와 자료 미포함 확정은 담당자가 원문 근거로 검토한다.

## 0. 이번 개정에서 바꾼 내용

1. 문서 칸·사용자 칸 구분을 유지하고, 질문별 활성화 여부와 필수도를 추가했다.
2. 필수도를 `필수 / 조건부 필수 / 선택`으로 통일했다. 답을 바꾸는 예외·신고·승인 조건은 단순 선택으로 처리하지 않는다.
3. 빈칸을 미확인·일부 확보·충돌·적용 안 됨·보유 자료로 확인 불가 등으로 구분했다.
4. 대표 유형 하나와 추가 요구 유형을 함께 선택해 복합 질문을 처리하도록 했다.
5. 과정·입학 구분·학생 상태를 분리하고, 사용자 조건을 요구하는 문서 근거를 연결하도록 했다.
6. 서비스 범위 밖과 현재 자료 미포함을 분리했다. 기존 미포함 표는 검증 대기 목록으로 보존했다.
7. 개발에 사용한 질문과 최종 평가 질문을 분리하고, 번역·유사 질문은 같은 묶음으로 관리하도록 했다.

## 1. 기본 원칙: 칸의 출처와 필요성을 따로 판단한다

### 1.1 칸은 두 종류다

| 종류 | 값을 채우는 근거 | 주의점 |
|---|---|---|
| 문서 칸 | 검색된 공식 자료의 본문·표·주석·관련 조항 | LLM 일반 지식이나 예시 답변으로 채우지 않는다. |
| 사용자 칸 | 현재 발언, 이전 대화, 사용자가 확인한 정보 | 질문 언어·이름으로 국적을 추정하지 않는다. 사례 조건과 사용자 본인 정보를 구분한다. |

**빈칸이라는 이유만으로 재검색하거나 되묻지 않는다.** 먼저 이번 질문에 필요한 항목인지, 조건부 항목의 발동 조건이 충족됐는지 판단한다.

### 1.2 질문별 활성화와 필수도

유형별 표는 모든 항목을 항상 요구하는 양식이 아니라, 질문별 체크리스트를 만드는 후보 목록이다.

| 필수도 | 정의 | 예시 |
|---|---|---|
| 필수 | 이번 질문의 핵심 답을 구성하는 데 반드시 필요 | “수업료 얼마?”의 금액·통화·산정 단위 |
| 조건부 필수 | 질문의 추가 요구 또는 문서의 적용 조건이 발동할 때 필요 | 국가별 추가 서류, 허용을 위한 사전 승인, 특정 학기의 신청 기한 |
| 선택 | 없어도 핵심 질문에 답할 수 있는 보완 정보 | 금액만 묻는 질문의 납부 장소 |

- 각 항목에 `활성화 여부`, `필수도`, `활성화 이유`를 기록한다.
- 사용자가 명시적으로 요구한 정보는 이번 질문에서 필수로 승격한다. 예: “서류를 언제 어디에 제출해?”의 기한·제출처.
- 조건부 항목의 발동 여부가 불명확하면 임의로 비활성화하지 않는다. 관련 문서를 확인하거나 조건별로 안내하고, 개인별 결론이 필요하면 사용자에게 확인한다.
- 선택 항목도 현재 조건에서 답의 정확성을 바꾸면 조건부 필수로 승격한다.
- 적용 안 됨으로 판정할 때도 이유를 남긴다. 찾기 어렵다는 이유로 필수 항목을 선택 또는 적용 안 됨으로 바꾸지 않는다.

### 1.3 답변 수준

- **완결 답변**: 활성화된 필수·조건부 필수 문서 항목이 근거로 충족되고, 적용 조건과 중요한 충돌이 해결된 경우.
- **조건별 일반 안내**: 사용자 조건이 없어도 문서상의 경우를 정확하게 나누어 설명할 수 있는 경우. 개인별 가능 여부는 확정하지 않는다.
- **추가 확인 질문**: 개인별 결론을 바꾸는 사용자 조건이 미확인이고, 조건별 일반 안내만으로 요청을 충족하기 어려운 경우. 가능한 일반 안내를 먼저 제공할 수 있다.
- **부분 답변**: 필요한 문서 근거를 끝내 확보하지 못하거나 충돌을 해결하지 못한 경우. 확인된 내용, 미확인 항목, 그 이유와 확인 경로를 구분한다.
- **확인 불가 안내**: 사용할 수 있는 근거가 전혀 없으면 억지로 부분 답변을 만들지 않는다. 문의처도 출처가 확인된 경우에만 제공한다.

## 2. 칸의 상태와 충분성 판정

### 2.1 문서 칸 상태

| 상태 | 의미 | 다음 행동 |
|---|---|---|
| `unchecked` 미확인 | 아직 관련 근거를 확인하지 않음 | 필요 항목이면 검색 |
| `supported` 근거 확보 | 적용 가능한 근거가 판정 기준을 충족함 | 답변에 사용 가능 |
| `partial` 일부 확보 | 목록·표·조건·관련 조항이 불완전함 | 원문 확장 또는 누락 항목 재검색 |
| `missing` 검색 후 미확보 | 검색은 했으나 답을 뒷받침할 근거를 찾지 못함 | 다른 검색어·출처로 재검색 가능; 자료 부재 확정 아님 |
| `conflicting` 충돌 | 적용 가능한 근거 사이의 차이를 해소하지 못함 | 시행 시점·대상·개정 관계 확인; 임의 우선순위 금지 |
| `not_applicable` 적용 안 됨 | 이번 질문에 불필요하거나 발동 조건이 성립하지 않음 | 이유를 기록하고 추가 확인 생략 |
| `unavailable_in_corpus` 보유 자료로 확인 불가 | 검토된 자료 범위표가 현재 문서 버전·대상에 대해 미포함을 확인함 | 해당 항목의 반복 검색 생략, 부분 답변 또는 자료 보강 |

검색 한도 소진은 `unavailable_in_corpus`의 근거가 아니다. `missing` 또는 `partial`을 유지하고 종료 사유를 `budget_exhausted`로 별도 기록한다. 도구 오류도 자료 부재와 구분한다.

**칸별 시도 상한.** 한 칸이 전체 검색 예산을 독차지하지 않도록 칸마다 신규 검색 최대 2회, 원문 확장 최대 2회로 제한한다(초기 설정값이며 평가로 조정한다). 상한에 도달한 칸은 그 질문에서 더 검색하지 않고 다음 후보 칸으로 넘어가지만, 상태는 바꾸지 않는다. `missing`·`partial`·`conflicting`을 그대로 유지하고, 종료 사유(칸별 상한 도달 또는 `budget_exhausted`)를 별도로 기록한다. 이렇게 남은 칸은 ④에서 부분 답변 대상이 되며, 확인된 내용·미확인 항목·이유·확인 경로를 구분해 안내한다. 이 경우에도 `unavailable_in_corpus`로 바꾸지 않는다.

### 2.2 사용자 칸 상태

| 상태 | 의미 | 처리 |
|---|---|---|
| `confirmed` 확인됨 | 사용자 발언 등에서 값과 근거 메시지를 확인함 | 같은 대화·사례에서 재사용 |
| `unknown` 미확인 | 필요한 값이 제공되지 않음 | 필요성이 입증된 경우에만 질문 |
| `ambiguous` 모호함 | 해석이 여러 개이거나 명확한 정정이 아닌 발언이 충돌함 | 해당 조건만 확인 |
| `not_required` 불필요 | 이번 답변에는 확인할 필요가 없음 | 묻지 않음 |

- 명확한 정정 발언은 최신 값으로 갱신하고 이전 값의 출처를 남긴다.
- “친구가 GKS 장학생인데…”는 친구 사례의 조건이다. 사용자 본인의 영구 프로필로 저장하지 않는다.
- 일반 규정을 묻는 “GKS 장학생은…”도 질문의 대상 조건이지, 사용자 본인이 장학생이라는 증거는 아니다.

### 2.3 모든 문서 항목의 공통 충족 기준

1. 문서가 해당 주제만 언급하는 것이 아니라, 항목에 필요한 값을 실제로 제공한다.
2. 질문의 대상·절차·트랙·적용 시점과 근거의 범위가 맞는다. 학기·시점이 핵심인 질문에서는 오래된 수치를 현재 값으로 제시하지 않는다.
3. 문서 ID, 버전, 페이지 또는 절, 청크 ID와 근거 구절을 연결할 수 있다.
4. 표의 주석, “다만”, “단”, “별도”, “준용” 및 이어지는 페이지를 필요한 범위까지 확인한다.
5. 근거끼리 충돌하면 `supported`로 확정하지 않는다. 문서 수집일은 시행일·개정일을 대신하지 않는다.
6. 명시적 금지, 해당 없음, 추후 공지 같은 내용도 문서가 그 사실을 명시하면 근거로 기록할 수 있다. 다만 “추후 공지”는 정확한 날짜나 신청 절차를 확보했다는 뜻이 아니다.
7. “예외가 없다”는 결론은 예외를 검색하지 못했다는 사실만으로 만들지 않는다. 예외 점검 항목에는 검토한 본문·관련 조항의 범위를 남긴다.

### 2.4 충분성 검증에서의 분기 규칙

| 상황 | 행동 |
|---|---|
| 근거와 적용 조건이 충분함 | 정상 답변. 마지막 검색에서 충분해졌다면 한도 도달 여부와 관계없이 정상 답변 |
| 사용자 조건이 없어도 짧고 명확한 조건별 안내가 가능함 | 조건별 일반 안내. 개인별 결론은 확정하지 않음 |
| 필요한 사용자 조건만 부족함 | `ask_clarification` 후 상태 저장, 사용자 답변을 받아 ①로 복귀 |
| 필요한 문서 근거가 부족하고 예산이 남음 | 누락 항목에 따라 재검색 또는 원문 확장 |
| 문서와 사용자 정보가 모두 부족함 | 일반 근거를 먼저 확보할 수 있으면 검색. 사용자 조건 없이는 유효한 다음 검색을 정할 수 없으면 되묻기 |
| 필요한 근거가 부족하고 예산 소진·칸별 상한 도달·새 근거 없음 | 부분 답변 또는 확인 불가 안내 |
| 현재 자료 버전에 대한 미포함이 검증됨 | 해당 항목의 반복 검색을 생략하고 나머지 근거는 계속 확인 |
| 도구 장애 | 제한된 재시도 후 장애와 미확인 부분 안내. “문서에 없음”으로 바꾸지 않음 |

## 3. 질문 유형: 대표 유형 1개 + 추가 요구

- 초기 유형은 T1~T6을 유지한다. 목록·종류와 서류는 판정 기준이 달라 우선 분리한다.
- 단어만으로 분류하지 않고 사용자가 요구한 답의 모양을 기준으로 고른다.
- 복합 질문은 대표 유형과 추가 요구 유형을 함께 기록하고 필요한 칸을 합친다. 같은 의미의 칸은 하나로 합친다.
- 단순 질문은 불필요하게 분해하지 않는다. 하위 질문이 필요하면 초기 최대 3개로 제한한다.
- 예: “아르바이트 가능해? 어떤 서류를 어디에 내?” → 대표 T5, 추가 T3·T4.
- 예: “결핵 증명서는 언제 내?” → 대표 T1의 기한 질문. ‘증명서’가 있다고 T3의 전체 서류 목록을 요구하지 않는다.

아래의 필수도는 유형 기본값이다. 1.2절에 따라 질문별로 활성화하며, 문서 내용에 따라 후속 검색에서 갱신한다.

### T1. 단순 사실

- 답의 모양: 금액, 날짜, 기간, 장소, 연락처 등 특정 값.
- 예시: “한국어학당 수업료가 얼마예요?”, “가을학기 지원 기간이 언제예요?”, “국제교류 담당 부서 연락처는?”

| 문서 칸 | 기본 필수도 | 충족 기준 |
|---|---|---|
| 요청한 값 | 필수 | 질문한 항목의 값이 명시됨. 금액은 통화·산정 단위, 기간은 시작·종료 또는 기준 사건을 함께 확인 |
| 적용 범위 | 필수 | 어느 과정·트랙·차수·시설 등의 값인지 확인. 전체 공통이면 그 범위를 기록 |
| 기준 시점 | 조건부 필수 | 모집 기간·비용 등 시점에 따라 달라지는 값이면 적용 학년도·학기·시행 시점을 확인 |
| 조건별 차이·변동 단서 | 조건부 필수 | 값을 바꾸거나 현재 값으로 단정하지 못하게 하는 주석이 있으면 포함 |
| 추가 안내 | 선택 | 질문의 핵심과 직접 관련 있는 보완 정보만 포함 |

- 사용자 칸 후보: 지원 학기, 교육 과정, 트랙, 시설 구분. 기본적으로 묻지 않되 적용 가능한 값을 고르는 데 필요하면 활성화한다.

### T2. 목록·종류

- 답의 모양: 제도·시설·전공 등 항목의 목록.
- 예시: “유학생 장학금 종류는?”, “학생 비자 종류는?”, “기숙사 시설에는 무엇이 있나요?”

| 문서 칸 | 기본 필수도 | 충족 기준 |
|---|---|---|
| 요청 범위의 목록 | 필수 | 관련 표·목록·주석과 이어지는 부분을 확인. 보유 자료의 범위 이상으로 ‘모든 종류’라고 단정하지 않음 |
| 적용 범위 | 필수 | 대상·트랙·학기 등 목록의 범위를 확인 |
| 항목별 대상·제외 조건 | 조건부 필수 | “내가 받을 수 있는 장학금”처럼 조건이 포함되거나, 목록에 포함/제외를 결정하는 조건이 있으면 확인 |
| 항목별 설명·금액 | 선택 | 사용자가 요구하면 필수로 승격 |

- 사용자 칸 후보: 트랙, 교육 과정, 학생 상태, 입학 구분. 단순한 종류 소개라면 조건별로 안내할 수 있다.

### T3. 서류

- 답의 모양: 제출 서류 또는 특정 서류의 준비 요건.
- 예시: “입학 지원 서류가 뭐예요?”, “재정 증명은 어떻게 준비하나요?”, “번역공증이 필요한가요?”

| 문서 칸 | 기본 필수도 | 충족 기준 |
|---|---|---|
| 요청한 서류·기본 목록 | 필수 | 전체 서류 질문이면 대상별 목록의 끝과 주석을 확인. 특정 서류 질문이면 그 서류에 필요한 정보만 확인 |
| 조건별 추가·대체 서류 | 조건부 필수 | 해당 입학 구분·재정 주체·발급 상황 등에 추가/대체 요건이 있으면 확인 |
| 형식·유효기간 | 조건부 필수 | 해당 서류의 인증·번역·원본/사본·발급일 요건을 확인. 특정 숫자는 실제 조항에서 추출 |
| 국가·발급지별 예외 | 조건부 필수 | 문서에 적용 갈래가 있을 때 확인. 국적·발급국·신청국을 혼동하지 않음 |
| 제출 방법·기한·장소 | 선택 | 사용자가 요구하거나 적법한 제출 여부를 결정하는 조건이면 필수로 승격 |

- 사용자 칸 후보: 입학 구분, 교육 과정, 트랙, 신청 위치, 국적, 서류 발급국, 재정 증명 주체. 관련 조항이 요구하는 항목만 활성화한다.

### T4. 절차

- 답의 모양: 목적을 달성하기 위한 행동 순서.
- 예시: “입학 지원은 어떻게 하나요?”, “등록금 납부 방법은?”, “기숙사 신청 절차는?”

| 문서 칸 | 기본 필수도 | 충족 기준 |
|---|---|---|
| 단계 순서 | 필수 | 요청 범위에서 시작·중간·완료 단계가 연결됨. 문서에 없는 단계를 상식으로 추가하지 않음 |
| 신청처·방법 | 필수 | 어디에 어떤 방법으로 진행하는지 확인. 일부 절차만 묻는 경우 해당 범위로 제한 |
| 선행 요건 | 조건부 필수 | 절차 시작에 자격·서류·사전 승인이 필요하면 확인 |
| 기한 | 조건부 필수 | 질문이 기한을 요구하거나 해당 절차에 기한이 적용되면 확인. 못 찾았다고 ‘기한 없음’으로 처리하지 않음 |
| 승인·신고·예외 | 조건부 필수 | 순서나 완료 여부를 바꾸는 승인·신고·예외가 있으면 확인 |
| 추가 안내 | 선택 | 질문 해결에 도움이 되는 출처 있는 정보 |

- 사용자 칸 후보: 교육 과정, 학생 상태, GKS 여부, 신청 위치, 절차 진행 단계.

### T5. 자격·허용·의무

- 답의 모양: 가능/불가능, 대상 자격, 해야 하는지와 그 조건.
- 예시: “GKS 장학생은 아르바이트할 수 있나요?”, “휴학할 수 있나요?”, “보험 가입이 의무인가요?”

| 문서 칸 | 기본 필수도 | 충족 기준 |
|---|---|---|
| 원칙 | 필수 | 허용·금지·의무·자격의 기본 규정을 확인 |
| 적용 범위 | 필수 | GKS/일반 학생, 과정, 기관, 시점 등 규정의 범위를 확인 |
| 허용 조건·한도 | 조건부 필수 | 원칙에 조건·한도가 붙으면 모두 확인. 금지만 명시된 규정에 허용 한도를 지어내지 않음 |
| 예외·관련 조항 점검 | 필수 | 본문과 연결된 예외·준용 조항을 검토하고 확인 범위를 남김. 확인하지 못한 관련 조항은 미확인으로 유지 |
| 승인·신고 절차 | 조건부 필수 | 승인·신고가 허용의 전제라면 필수. 가능 여부만 묻더라도 생략하지 않음 |

- 사용자 칸 후보: GKS 여부, 교육 과정, GKS 단계, 학위 수준, 재학 학기, 시점, 신청 사유. 문서상 분기를 바꾸는 항목만 확인한다.

### T6. 결과·제재·구제

- 답의 모양: 특정 행동·상황의 결과, 제재 사유 또는 구제 방법.
- 예시: “비자가 거부되면 환불되나요?”, “휴학 후 복학하지 않으면?”, “GKS 장학생이 경고받는 경우는?”

| 문서 칸 | 기본 필수도 | 충족 기준 |
|---|---|---|
| 질문한 사건·사유 | 필수 | 어떤 사건이 결과를 일으키는지 확인. 특정 사건 질문에는 무관한 전체 사유를 요구하지 않음 |
| 사유 전체 목록 | 조건부 필수 | “어떤 경우에 경고받나?”처럼 전체 사유를 요청할 때 목록·주석의 끝까지 확인 |
| 결과·조치 | 필수 | 해당 사건에 연결되는 결과와 필요한 조건을 확인 |
| 적용 범위 | 필수 | 누구에게 언제 적용되는 조치인지 확인 |
| 예외·구제·기한 | 조건부 필수 | 결과를 바꾸는 예외 또는 요청된 이의신청·환불·복구 방법과 기한이 있으면 확인 |

- 사용자 칸 후보: GKS 여부, 교육 과정, 학위 수준, 실제 발생한 사건, 발생 시점. 불필요한 개인 사정은 수집하지 않는다.

## 4. 사용자 칸 목록과 되묻기 규칙

### 4.1 필드 후보

다음은 허용 후보이며 필수 질문 목록이 아니다. 값이 필요해지는 근거는 실제 문서 ID·조항으로 연결해야 한다.

| 필드 | 값 예시 | 활성화 조건 |
|---|---|---|
| 교육 과정 | 어학연수 / 학부 / 대학원 | 해당 문서에서 과정별 규정이 다름 |
| 입학 구분 | 신입 / 편입 | 입학 요건·서류 등이 달라짐 |
| 편입 학년 | 2학년 / 3학년 | 편입 질문이며 학년에 따라 적용 내용이 달라짐 |
| 학생 상태 | 지원 예정 / 합격 / 재학 / 휴학 | 같은 제도의 적용 조건이 상태별로 다름 |
| 수업 트랙 | 한국어 / 영어 | 모집요강·비용·자격 등의 기준이 다름 |
| GKS 여부 | 예 / 아니오 / 미확인 | 해당 사례에 GKS 규정을 적용할지 결정해야 함 |
| GKS 단계 | 한국어연수 / 학위과정 | GKS 규정이 단계별로 다름 |
| 학위 수준 | 학사 / 석사 / 박사 | 해당 조항이 학위 수준별로 다름 |
| 지원 학년도·학기·차수 | 사용자가 지정한 값 | 모집 기간·대상·요건이 달라짐 |
| 재학 학기 | 첫 학기 등 | 관련 규정의 적용 여부가 달라짐 |
| 활동·신청 시점 | 학기 전 / 학기 중 / 방학 / 특정 날짜 | 해당 조항이 시점별로 다름 |
| 현재 체류 위치 | 국내 / 해외 및 필요 시 국가 | 문서가 현재 체류 위치를 조건으로 함 |
| 신청 국가·기관 | 실제 신청할 국가·기관 | 관할에 따라 서류·비용·절차가 다름 |
| 국적 | 필요한 경우 사용자가 제공한 값 | 문서에 국적별 적용 규정이 있음 |
| 서류 발급국·발급 기관 | 필요한 경우 사용자가 제공한 값 | 학력 인증 등의 요건이 발급국·기관에 따라 다름 |
| 신청 사유·현재 진행 단계 | 질문 해결에 필요한 최소 정보 | 문서가 그 사유·단계에 따라 답을 달리함 |
| 기타 문서로 입증된 조건 | 예: 재정 증명 주체, 시설 구분 | 사전 후보로 처리할 수 없고 실제 조항이 해당 구분을 요구함 |

- 동아대 전용 서비스라는 기관 범위와 사용자의 실제 소속은 구분한다. 기본 기관을 동아대로 안내할 수 있으나, 사용자 재학 사실을 자동 확정하지 않는다.
- 후보 밖 조건이 필요하면 문서 근거와 필요 이유를 첨부하여 임시 조건으로 기록한다. LLM이 영구 설정의 필드나 규정 수치를 임의로 추가하지 않는다.

### 4.2 되묻기 규칙

1. 일반 안내가 가능한 질문이면 먼저 문서를 검색한다. 개인 조건이 없다는 이유만으로 시작부터 차단하지 않는다.
2. 해당 값이 결론을 바꾸는 문서 근거가 있고 개인별 결론이 필요한 경우에 묻는다. 문서가 너무 광범위해 최초 검색 자체를 정할 수 없으면 요청 대상만 좁히는 질문을 할 수 있다.
3. 갈래가 2~3개이고 짧고 명확하게 설명할 수 있으면 조건별로 안내한다. 다만 사용자가 본인의 확정 결론을 원하면 필요한 조건을 확인한다.
4. 한 번에 최대 2개 항목을 묻고, 이미 확인된 값은 다시 묻지 않는다. 답변이 여전히 모호하면 그 항목만 확인한다.
5. 문서의 빈칸을 사용자에게 규정을 설명해 달라는 질문으로 전가하지 않는다. 사용자 칸은 개인 상황·요청 범위 확인용이다.
6. 사용자 응답을 기다릴 때 현재 HTTP 요청은 종료하되 대화 상태는 저장한다. 응답 후 조건을 갱신해 ① 질문 분석으로 돌아간다.
7. 사용자가 모르거나 답변을 원하지 않으면 반복해서 요구하지 않고, 가능한 조건별 안내 또는 판단 한계를 제공한다.
8. 국적, 체류자격, GKS 여부 등을 언어·이름·다른 조건에서 추정하지 않는다.

## 5. 보유 자료의 확인 범위: 체크리스트와 별도 관리

### 5.1 구분

- **서비스 범위 밖**: 서비스가 다루지 않기로 정한 주제. 명백한 경우 범위를 안내한다.
- **보유 자료로 확인 불가**: 서비스 범위 안이지만 현재 자료로 특정 항목을 확인할 수 없음.
- **검색 후 미확보**: 검색 결과에서 못 찾았을 뿐, 전체 자료의 미포함 여부는 확정하지 못함.

자료 확인 범위표에는 `주제/항목`, `대상`, `검토 문서 ID·버전`, `검토 위치·범위`, `검토자`, `검토일`, `포함 상태`를 기록한다. 포함 상태는 `검토 대기 / 포함 / 일부 포함 / 미포함 확인`으로 구분한다.

현재 질문과 대상이 일치하고, 검토 후 해당 자료 집합이 변경되지 않은 `미포함 확인` 항목에 한해서 반복 검색을 생략한다. 문서가 추가·교체·삭제되면 영향을 받는 기록을 다시 검토한다.

### 5.2 v0의 문서 범위 점검 내용을 보존한 검증 대기 목록

아래는 초안 작성자의 관찰이다. 이번 개정에서 PDF 원문을 재검증하지 않았으므로 **즉시 검색 차단 규칙으로 사용하지 않는다.** 문서 버전·페이지·검토 범위를 보완한 뒤 5.1의 상태를 확정한다.

| 수강신청 방법 | 영어트랙 자료의 “오리엔테이션에서 안내” | 실제 단계·시스템 사용법 | 검토 대기 |

### 5.3 적용 대상·시점 점검 후보

다음도 v0의 관찰이며 원문 확인이 필요하다.

1. “Study in KOREA! 한국 유학 가이드”라는 파일은 v0에서 KVAC 헤이그 비자신청 자료, 2024.05 업데이트, 유로 수수료를 포함한 자료로 보고됐다. 확인되면 일반 한국 유학 안내서로 취급하지 말고 기관·관할·신청 위치·기준 시점을 메타데이터에 반영한다. 국적만으로 관할을 결정하지 않는다.
2. GKS 대상 지침을 비GKS 학생의 일반 규정으로 확장하지 않는다. 일반 질문에는 GKS 대상임을 명시한 제한적 안내만 가능하며, 비GKS 기준은 별도 근거가 필요하다.
3. 모집요강은 v0에서 2026학년도 후기 자료로 보고됐다. 일부 표에 2024학년도 기준 문구가 있다는 관찰도 있으므로 문서 전체 날짜와 개별 표의 기준을 구분해 검토한다.
4. 현재 날짜·학생의 지원 학기를 문서 적용 시점과 비교한다. 파일명이나 수집일만으로 최신 자료임을 확정하지 않는다.

### 5.4 구체 규정·수치의 취급

v0 사용자 칸 표에 제시된 TOPIK 등급, 등록·전형료, 재정 증명 금액, GKS 경고·귀국 연기 기준, 국가별 예외 등의 값은 체크리스트 설정에 고정하지 않는다. 원문 대조 후 문서 근거로 관리한다. v0 원본은 별도 백업으로 보존하며, 해당 수치가 이번 개정에서 검증됐다는 의미는 아니다.

## 6. 설정 파일과 질문별 실행 데이터

### 6.1 정적 설정과 동적 상태 분리

초기 설정 파일 하나 안에 다음 영역을 구분해 둘 수 있다.

| 영역 | 내용 | 프롬프트 사용 |
|---|---|---|
| `profiles` | T1~T6의 설명, 예시, 문서 칸·필수도·활성화 조건·판정 기준 | ①은 요약을 보고 유형·후보 항목 선택 |
| `user_fields` | 사용자 칸 정의와 허용 값·출처 규칙 | 필요한 후보만 전달 |
| `policies` | 되묻기, 예산, 종료, 근거 검증 규칙 | 관련 단계에 전달; 서버도 한도를 강제 |
| `coverage_registry` | 보유 자료별 검토 범위·버전·상태 | 질문·대상과 관련된 검증 기록만 조회 |

체크리스트 전체, 문서 본문, 범위표 전체를 매번 한 프롬프트에 넣지 않는다. ①에는 유형 요약, 선택된 유형의 상세 기준은 ②·④에 전달한다. 설정이 작을 때도 문서 근거와 실행 상태를 정적 규칙에 섞지 않는다.

### 6.2 질문별 체크리스트의 최소 필드

| 필드 | 용도 |
|---|---|
| `slot_id`, `label`, `source_type` | 항목 ID, 이름, 문서/사용자 구분 |
| `active`, `requirement`, `activation_reason` | 활성화 여부, 필수도, 이번 질문에 필요한 이유 |
| `activation_state`, `depends_on` | 조건부 발동의 확인/미확인 상태와 필요한 문서·사용자 항목 |
| `criterion`, `status`, `value` | 판정 기준, 현재 상태, 확인한 값 |
| `evidence_refs` | 문서 ID·버전·페이지·청크·근거 구절 |
| `user_message_refs` | 사용자가 제공한 조건의 메시지 ID와 발언 |
| `missing_detail`, `next_action` | 남은 확인 사항과 다음 행동 |

예시 구조:

```yaml
case:
  question: "GKS 장학생은 아르바이트할 수 있어?"
  primary_type: T5
  additional_types: []
  answer_scope: general
  conditions:
    scholarship:
      value: GKS
      source_message_id: m1
      subject: question_target  # 사용자 본인 정보로 확정하지 않음
  document_slots:
    - slot_id: permission_rule
      active: true
      requirement: required
      status: unchecked
      criterion: "대상과 적용 시점이 맞는 허용·금지 원칙 및 근거 위치 확인"
      evidence_refs: []
    - slot_id: approval_requirement
      active: true
      requirement: conditional
      activation_state: unresolved
      status: unchecked
      criterion: "승인·신고가 허용의 전제인지 원문 확인"
      evidence_refs: []
  user_slots:
    - slot_id: gks_stage
      status: unknown
      active: false  # 아직 개인별 결론을 요구하지 않으며 조건 필요성도 미확인
      required_by_evidence: []
  next_action: search
```

`unchecked` 상태에서 LLM이 허용 여부를 채우지 않는다. 검색 후 근거에 따라 사용자 칸을 활성화하고, 일반 안내로 충분한지 또는 개인 조건 확인이 필요한지 결정한다.

## 7. 단계별 책임과 초기 예산

| 단계 | 책임 | 출력 |
|---|---|---|
| ① 질문 분석 | 대화 연결, 일반/개인 사례 구분, 대표·추가 유형 선택, 후보 항목과 최초 하위 질문 식별 | 초기 체크리스트·확인된 사례 조건 |
| ② 검색 계획 | 필요한 항목별 검색어·출처 범위·검색 순서 결정 | 검색 계획; 재검색 시 누적 근거·미해결 항목 반영 |
| ③ 근거 검색 | Hybrid+BGE 검색, 필요한 경우 원문 확장, 근거 누적·중복 제거 | ID·버전·페이지가 있는 근거 목록 |
| ④ 충분성 검증 | 항목 상태·발동 조건·충돌 확인, 사용자 조건 필요성 갱신 | 답변 / 재검색 / 원문 확장 / 되묻기 / 부분 답변 |
| ⑤ 답변 생성 | 확인된 근거로 요청 범위에 맞게 답변 | 주장과 출처 연결, 조건·미확인 사항 표시 |

- 검색 후 새 항목이 필요하면 기존 유형의 조건부 항목을 활성화한다. 기존 설정으로 처리하지 못하는 근거 있는 항목은 이번 사례의 임시 추가 항목으로 표시하고 추후 설정 검토 대상으로 남긴다.
- LLM이 반환한 구조는 서버에서 스키마·허용 행동·문서 ID 존재 여부를 검사한다. 구조가 맞아도 판정 내용까지 정답이라는 뜻은 아니다.
- 초기 예산안: 하위 질문 최대 3개, 최초 검색과 추가 검색 최대 1라운드, 검색 호출 총 6회, 원문 확장 총 3회. 최적값이 아니라 평가로 조정할 설정이다.
- 칸별 시도 상한: 칸 하나당 신규 검색 2회, 원문 확장 2회(2.1절). 상한에 도달한 칸은 상태를 유지한 채 검색만 중단하며, 총 예산과 별개로 서버가 강제한다. 초기 설정값이며 평가로 조정한다.
- 동일 질문·필터·문서 버전의 반복 호출은 재사용하고, 새 근거가 없으면 반복을 멈춘다.
- 사용자 응답으로 새 요청이 시작되면 요청별 예산은 새로 부여할 수 있지만, 기존 질문·근거·시도 기록은 유지한다. 문서 버전이 바뀌면 기존 근거의 유효성을 다시 확인한다.
- 문서 내용은 근거로만 읽는다. 문서 안의 지시문이 도구 호출·사용자 정보 처리 규칙을 변경하지 못하게 한다.

## 8. 초안 점검과 평가 계획

### 8.1 문서 대조

1. 각 유형에서 질문 2~3개를 골라 체크리스트를 수동 작성한다.
2. 각 활성 항목에 문서 ID·버전·페이지·근거 구절을 연결한다.
3. 실제 문서로 채울 수 없는 항목은 검색 실패인지, 검토 범위의 미포함인지 구분한다.
4. 전체 자료에 없다고 확정하려면 문서별 관련 범위와 검토자를 기록한다. 몇 개 예시 검색만으로 미포함을 확정하지 않는다.
5. 기본 질문 외에 조건별 예외, 표·목록의 다음 페이지, 적용 연도 불일치, 문서 충돌 사례를 점검한다.

### 8.2 질문 집합 분리

- few-shot 66개와 평가 질문 30개가 서로 겹치거나 번역 관계인지 먼저 점검한다. 단순 합산하여 서로 독립적인 96개 질문으로 취급하지 않는다.
- 프롬프트·유형·체크리스트 수정에 사용한 질문은 개발 또는 회귀 테스트로 분류한다.
- 최종 평가에는 수정 과정에서 사용하지 않은 별도 질문을 둔다. 기존 30개를 계속 보며 설계를 고쳤다면 개발용으로 전환하고 평가 질문을 새로 확보한다.
- 같은 질문의 한국어·영어·베트남어 버전, 유사 표현, 같은 상황의 파생 질문은 한 묶음으로 나눈다. 개발/평가 사이에 같은 묶음을 분산하지 않는다.
- 최종 평가용 기준에는 유형뿐 아니라 활성 항목, 조건부 발동, 근거 위치, 필요한 확인 질문, 예상 다음 행동을 기록한다.

### 8.3 점검 지표

| 지표 | 확인할 문제 |
|---|---|
| 대표·추가 유형 판정 | 복합 요구를 놓치거나 단어만 보고 분류하는가? |
| 필수 항목 누락 | 답을 바꾸는 조건·예외·서류를 빠뜨리는가? |
| 불필요 항목 활성화 | 좁은 질문에 전체 체크리스트를 강제하는가? |
| 출처 구분 오류 | 문서 정보를 사용자에게 묻거나 개인 조건을 문서에서 찾는가? |
| 근거 없는 충족 판정 | 근거 ID가 없거나 인용이 내용을 뒷받침하지 않는데 채웠다고 하는가? |
| 불필요·필요 되묻기 | 일반 안내가 가능한데 막거나, 개인별 필수 조건을 확인하지 않는가? |
| 다음 행동·종료 | 원문 확장, 재검색, 부분 답변을 상황에 맞게 고르는가? |
| 대화·다국어 일관성 | 후속 메시지·정정·번역 질문에서 같은 조건과 규칙을 유지하는가? |

실패 사례를 보고 유형을 합치거나 설명을 수정한다. 형식 검사와 별도로 사람의 근거 검토를 수행한다. 한 번 검색, 고정 하위 질문 검색, 결과 기반 재계획을 같은 문서 버전과 평가 질문으로 비교한다.

## 9. 확정·검토할 사항

| 항목 | 이번 권고 | 확정 조건 |
|---|---|---|
| 유형 수 | T1~T6 유지, 복합 유형 허용 | 개발 질문에서 분류 충돌을 확인한 뒤 조정 |
| 짧은 갈래 안내 | 2~3개 갈래를 명확히 설명할 수 있으면 되묻기보다 조건별 안내 | 개인별 결론 요청 여부를 함께 판단 |
| 관할이 제한된 비자 자료 | 범위 메타데이터를 확인하고 해당 관할 질문에만 사용 검토 | 팀이 원문·관할·기준 시점을 확인 |
| 자료 보강 | 학칙 세부·일반 유학생 관련 기준 등 실제 미포함 항목 우선 검토 | 필요 문서와 최신 공식 출처 확인 |
| 자료 미포함 표 | v0 관찰은 검증 대기로 유지 | 현재 자료 집합의 버전·검토 범위 기록 |
| 담당 분리 | 작성자 초안 → AI의 구조·누락 검토 → 팀의 원문 근거 승인 | 변경 이력과 승인된 설정 버전 보존 |

## 10. 구현 전 최소 확인 시나리오

1. “수업료 얼마?”에 불필요한 제출 서류·절차를 요구하지 않는다.
2. “GKS 장학생 아르바이트 가능?”에 사용자 과정을 먼저 강제하지 않고 일반 규정을 검색한다.
3. “가능하면 어떤 서류를 어디에 내?”에서 T5·T3·T4의 요구를 함께 처리한다.
4. 국가별 예외 근거가 없을 때 국적을 묻지 않는다. 국적과 신청국·발급국을 구분한다.
5. 마지막 허용 검색에서 근거가 충분해지면 정상 답변한다.
6. 서류 목록이 다음 페이지로 이어지면 일부 확보로 판정하고 확장한다.
7. 검색 결과가 없거나 도구가 실패했다고 보유 자료 미포함으로 확정하지 않는다.
8. “추후 공지”를 찾았을 때 정확한 날짜·절차를 만들어내지 않는다.
9. 친구 사례, 일반 규정 문의, 사용자의 본인 조건을 구분한다.
10. 문서 추가·교체 후 오래된 미포함 기록 때문에 새 근거 검색을 건너뛰지 않는다.
